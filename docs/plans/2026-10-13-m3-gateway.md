## What changed since the master plan

### The four flags of the M1 review (issues #1 to #4)

| Flag | Decided | Where |
|---|---|---|
| **#1 Durable active version per agent** | The record lives in **control**, not in the gateway's working database: a Firestore database of its own, `releases`, document `policy_versions/{agent}` = `{version, sha256, by, at}`. Its own database, because `control-ui` holds `datastore.user` on the whole control project today and could otherwise write the record: its role gets an IAM condition that limits it to database `control` (checked against Google's docs at implementation; if Firestore cannot condition it, this goes back to Matthijs before anything is built). Matthijs's publish step writes it (new command `aiven-policy publish`, Task 3.5b) in a transaction that only lets the version go up. The gateway loads a policy only when its version and hash **equal** that record, and never below its own working high-water mark (`active/{agent}` in Firestore `gateway`, which may be rebuilt empty). No record (Firestore says it does not exist) means the agent is not published: `NO_POLICY`. A record that cannot be read: refuse and alert, never "new agent". | Tasks 3.5, 3.5b; spec change (below) |
| **#2 Catalog signature** | Its own SSH namespace, **`aiven-catalog-v1`** (Matthijs: "its OWN namespace, e.g. aiven-catalog"; `-v1` matches `aiven-policy-v1`). A policy signature can never verify as a catalog signature, nor the reverse. `allowed_signers` becomes `matthijs namespaces="aiven-policy-v1,aiven-catalog-v1" <key>`. The gateway verifies the catalog before it parses it, and loads no policy without a valid one; the verified catalog's hash goes on every audit entry. | Tasks 3.0, 3.5; spec change (below) |
| **#3 Bytes read before verify** | Every object read from the policy bucket is capped: a policy, the catalog, `allowed_signers` and `pricing/models.yaml` at `MAX_FILE_BYTES + 1`, a signature at `MAX_SIG_BYTES + 1`. The size in the object's metadata is checked first, and the read itself is ranged to the cap (the object can change in between). Too large: refused with E-FILE-SIZE (E-SIG-INVALID for a signature) and an alert, without reading the rest. | Task 3.5 (`bucket_io.py`) |
| **#4 Pinned `ssh-keygen`** | `verify` takes the path of `ssh-keygen` as an argument; the gateway passes `/usr/bin/ssh-keygen`, fixed in code, never from a request or a file, and gives it a minimal `PATH` and a private `0700` temporary folder made at startup. At startup it checks that the binary exists, is a regular file owned by root and writable by nobody but root; otherwise it loads no policy and alerts. The image installs OpenSSH at a pinned version on a base image pinned by digest. | Tasks 3.0, 3.5, 3.10 |

### `CONTROL_UNREACHABLE` when the audit log fails too

M2's alert policy 2 counts `CONTROL_UNREACHABLE` refusals **in the audit log** (ruling R139). When
the gateway cannot write the audit log either (Cloud Logging down, or the gateway's write access
to control gone), nothing reaches that log, and no alert fires. The fallback:

1. **A line of its own.** Every fail-closed refusal (`CONTROL_UNREACHABLE`, and every refusal
   because an audit write failed: "no log, no action") also prints one structured line on
   stdout: `{"severity": "ALERT", "message": "gateway fails closed", "reason": ..., "alert": true,
   "audit_write_failed": true|false}`, with IDs only. Cloud Run stores it in the **gateway**
   project's own log, which needs nothing from control. This is the pattern of the functions
   (ruling R130).
2. **An alert on that line.** A log-based metric `aiven/gateway-fails-closed` on the gateway
   service's own lines, and an alert policy "the gateway fails closed for more than a minute" on
   it (> 0 for 60 s), plus a log-match alert on `audit_write_failed=true`. Where they live is
   checked against Google's docs at implementation (ruling to record): (a) in control, with the
   gateway project added to control's metrics scope, so the email channel stays one; or (b) in
   the gateway project, with Monitoring turned on there and an email channel of its own. (a) is
   preferred; (b) is the fallback.
3. **A drill.** KS-4 (remove the gateway's read access to control) proves the audit-log path;
   **KS-4b**, new: remove the gateway's `logging.logWriter` on control as well, make one call,
   and the fallback email must arrive, then restore. Both in the M3 runbook, and in the M3
   one-click script if Matthijs wants one (question 3 below).

### Carried over from M2

- **TTL.** The gateway sets `expire_at` = now + 90 days on every `runs/` and `calls/` document
  (ruling R106; the TTL policy exists since Task 2.2). Test: every write carries it.
- **Names from Terraform.** The bucket names are `<control>-policies` and `<control>-snapshots`
  (ruling R125). The gateway gets them, the control project and the region from environment
  variables that Terraform sets (`run.tf`), never from a file an agent can reach.
- **One audit writer.** The gateway uses `aiven.common.audit.AuditLog` (Task 2.3): `AuditWriteFailed`
  is the "no log, no action" signal of Task 3.4.
- **Who may call.** `run.invoker` on the gateway service for each `agent-<id>` and for
  `control-ui` only (§3, §8 break glass step 3). Cloud Run min 0, max 2 (§13).
- **Deploy check.** The `iam` group's `NOTE iam gateway service` becomes a real check (invokers are
  exactly the agents and `control-ui`); new: the service's image is pinned by digest, its
  service account is `gateway@`, ingress and min/max match §13, and the fail-closed alert exists.
- **The one-click script** stays an M2 tool. Its plan summary and the runbook's counts change
  where M3 adds resources (for example Monitoring in the gateway project under (b) above).

## Spec changes for sign-off (proposed)

1. **gateway-design §5, control table:** add Firestore database `releases` with

   UI's `datastore.user` is limited to database `control` by an IAM condition, so only Matthijs
   writes the record.
2. **validator-spec §2 and §5:** the catalog is signed under namespace `aiven-catalog-v1`;
   `allowed_signers` lists both namespaces; the signing and checking commands for the catalog.
3. **gateway-design §10:** the fail-closed alert also reads the gateway's own lines (the fallback
   above), like the functions' lines.
4. **validator-spec §3.10:** E-VERSION-ORDER reads "lower than the published record, or equal to
   it with a different hash"; a policy that differs from the record is not loaded.

### Task 3.5 additions: registry with flags #1 to #4

**Files:** add `src/aiven/gateway/bucket_io.py` (the capped reader), `src/aiven/gateway/startup.py`

**Interfaces:**

- `read_capped(bucket, name, cap) -> bytes`: metadata size first, then a ranged read of `cap + 1`

  `CATALOG_NAMESPACE` before parsing.
- `PolicyRegistry.refresh(now)`: per agent, reads the record (`ControlReader.policy_version`) and
  loads the bucket's file only when version and hash equal it and are not below `active/{agent}`.

### Task 3.5b: `aiven-policy publish` (flag #1, Matthijs's side)

**Files:** `src/aiven/policy/publish.py`, `tests/policy/test_publish.py`; dependencies
`google-cloud-storage` and `google-cloud-firestore` in a dependency group (two weeks old, ruling
R131).

**Interfaces:**

- `aiven-policy publish policies/<agent>.md --sig policies/<agent>.md.sig`, run with Matthijs's own
  login: validates and verifies the file locally (against the control project's
  `allowed_signers`, read capped), then in one Firestore transaction checks that the version is
  above the record (or there is none), uploads the file and its signature with
  `ifGenerationMatch`, and writes `policy_versions/{agent}`. A failure in between leaves the record
  as it was; a file uploaded without its record is never loaded.
- `--catalog catalog/catalog-v1.yaml --sig ...` publishes the catalog the same way (namespace
  `aiven-catalog-v1`).

**Tests:** `test_publish_refuses_a_lower_or_equal_version`, `test_publish_refuses_an_unsigned_file`,
`test_record_written_only_after_both_uploads`, `test_publish_never_prints_a_value` (on a fake bucket
and a fake Firestore).

**Commit:** `feat(policy): publish a signed policy and its version record`
