# M1 decisions: the policy validator

These are the rulings taken while building the validator (milestone M1), where the spec was silent, the plan conflicted with the spec, or a review raised a choice. Each reads: what was decided — why — what it costs if wrong. The spec stays binding; the rulings that changed spec text are marked SPEC and are listed for sign-off in the M1 report.

## Before Task 1.1 (pre-flight scan of the plan)

- **R1**: `valid_base()` (tests/support/policies.py, created in Task 1.2) = the template text with `REPLACE_ME_AGENTS_PROJECT` → `aiven-agents-test` and `REPLACE_ME_FOLDER_ID` → `1aBcDeFgHiJkLmNoPqRsTuVwXyZ012345` replaced everywhere (front matter and generated sections), written as `invoice-reminder.md` — the generated sections are a faithful render, so textual substitution equals re-rendering; Task 1.5 adds `test_valid_base_matches_render` to prove it — cost if wrong: base fixtures drift from the renderer, caught by that test.
- **R2**: Task 1.2 creates the single entry point `aiven.policy.validate.validate_file(path: Path, data: bytes, cfg: PlatformConfig, catalog: Catalog) -> list[Finding]` (findings sorted: file-level first, then by line, then column); Tasks 1.3–1.6 extend it; Task 1.7 verify() and Task 1.8 CLI call it — the plan named per-check functions but no aggregator — cost if wrong: one rename later.
- **R3**: test_codes compares findings(mutated) against findings(valid_base) as a multiset difference: the NEW findings must be exactly `[code]` at `expected_line`; findings that disappear are ignored — baseline warnings (W-TOOL-NOT-LIVE) would otherwise make "exactly [code]" impossible — cost if wrong: a mutation that silently removes a finding goes unnoticed (low risk; each code also has its own case).
- **R4**: `build_policy` returns a Policy even when fields hold placeholders (E-PLACEHOLDER reported; that field's other checks skipped), so `render` works on the template; it returns None only when required structure is missing or a type is wrong — spec §3.1 says placeholder fields skip their other checks — cost if wrong: render golden test can't run on the template.
- **R5**: `catalog/schemas/` holds one strict JSON Schema per grantable Drive and Email action (drive.list, drive.read, sheets.read, drive.create, drive.update, sheets.write, gmail.read, gmail.draft, gmail.send), with arguments taken from drive-wrapper §3 and email-wrapper §4; Agent Builder schemas come with wrap 3 (out of scope); R3 actions get none — cost if wrong: schemas added later.

## Task 1.1

- **R6**: keep the session-level commit trailer on subagent commits (attribution as instructed) — consistency over per-agent model naming — cost if wrong: cosmetic, fixable by amend before merge.
- **R7**: test_placeholder_skips_other_checks_for_that_field moves from Task 1.2 to Task 1.4 — field checks do not exist until 1.4, so the test would be vacuous in 1.2 — cost if wrong: none (test still lands in M1).
- **R8**: E-FILENAME moves from Task 1.2 to Task 1.3 — it needs the agent id from the loaded front matter, which 1.3 produces — cost if wrong: none (case still lands in M1).
- **R9**: Task 1.2's "JSON output" leg of test_content_findings_never_contain_value checks json.dumps(asdict(finding)) until the CLI --json exists; Task 1.8 extends it to the real output — the CLI is built in 1.8 — cost if wrong: none.
- **R10**: CR is owned by E-LINE-ENDINGS and the leading BOM by E-ENCODING; neither also counts as E-HIDDEN-CHAR (one defect, one code; the file fails either way). U+FEFF elsewhere stays E-HIDDEN-CHAR — cost if wrong: a lone CR is reported as a line-ending problem rather than a hidden one; the file still fails.
- **R11**: E-ENCODING, E-LINE-ENDINGS, E-FINAL-NEWLINE, E-FILE-SIZE report once per file (first bad line where it has one); E-HIDDEN-CHAR, E-PLACEHOLDER and content hits report per occurrence with line and column — spec "report everything, sorted by line"; per-line CR findings would flood a CRLF file — cost if wrong: re-shaping finding counts.
- **R12**: E-PLACEHOLDER matches whole words, case-sensitive (`\bREPLACE_ME\w*`, `\b(?:TODO|TBD|FIXME)\b`) — keeps random Drive IDs from matching — cost if wrong: "TODOs"/"xTODO" slip through (rare, still visible to the signer).
- **R13**: content-safety patterns fixed in task-1.2-brief.md (14 kinds, per-line, overlap dedupe in pattern order, IBAN candidate algorithm, card separators, standalone BSN) — the spec names the kinds but not the regexes — cost if wrong: a false positive blocks signing (fail closed) or an odd format slips through (spec §8 already admits disguised values).
- **R14**: secret-like test strings are built at test time from fragments; no token-shaped literal is committed — GitHub push protection and the "no credentials stored anywhere" rule — cost if wrong: none.
- **R15** (for Task 1.5): E-BODY-DRIFT compares the last generated section without the file's trailing newline(s), which E-FINAL-NEWLINE owns — otherwise the E-FINAL-NEWLINE cases in test_codes also produce E-BODY-DRIFT — cost if wrong: a test case needs two expected codes.

## Task 1.2

- **R16**: accept the JWT left boundary (?<![A-Za-z0-9_-])eyJ — the brief's regex is quadratic on long token runs (about 8 min at 1 MB) and scan() runs on agent payloads in M4/M6 — cost if wrong: a JWT glued to a preceding word character is missed.
- **R17**: tighten patterns in the fix round: (a) assignment keywords may follow an identifier prefix ending in _ - or . (db_password=, x-api-key:, aws.secret=) but never directly a letter or digit; (b) left boundary (?<![A-Za-z0-9]) on the prefix patterns sk-ant-, sk-, gh*_, github_pat_, xox*-, AIza, ya29., 1//0, AKIA/ASIA; (c) the PEM pattern also matches "PRIVATE KEY BLOCK" (PGP armor) — the brief's literal rules missed common credential names and flagged "risk-adjusted-..." prose as a key — cost if wrong: "max_token: 4096" is flagged (fail closed, clear message).
- **R18**: one sanitizing guard inside Finding.__post_init__ (helper in content.py): a param with any scan() hit becomes [hidden]; non-printable characters are escaped as \uXXXX; params are cut to 200 characters; path is escaped too. It replaces the per-site safe_echo planned for Task 1.3 — every producer (validate, check_set, verify, CLI) gets it for free, and a Finding can never hold a raw sensitive value or forge an output line (closes the Task 1.1 deferred format_line minor for params and path) — cost if wrong: an innocent param shows [hidden] (fail-safe).
- **R19**: the Finding guard hides a param when scan() hits OR any kind matches with no boundary conditions (loose prefixes, assignment, IBAN/card/BSN windows with the real validators) — hiding costs nothing, and a glued value (REPLACE_ME_FOLDER_ID + pasted value, the realistic mistake) must never print; scan() keeps its boundaries (R17b) against false positives in prose/base64 — cost if wrong: an innocent param shows [hidden].
- **R20**: accept the JWT first-segment cap (300) and left boundary (?<![A-Za-z0-9]) — keeps the pattern linear after R17(b) — cost if wrong: a JWT with a header over 300 characters is missed (real headers are far shorter).
- **R21**: card+OAuth overlap resolves by priority order (OAuth wins); task-1.2-fix-1.md misstated the expected result — cost if wrong: none (the line is reported either way).
- **R22**: E-PLACEHOLDER prints only the placeholder's own name (longest prefix of the form REPLACE_ME(_[A-Z0-9]+)*, then "…" when more follows), and hides the token when the whole surrounding non-space word is sensitive — a producer must never hand the guard a cut-off prefix — cost if wrong: an unrecognised glued value shows only its uppercase/digit part (recognised kinds are hidden).
- **R23**: message() re-applies safe_text at output; Task 1.8's JSON writer must do the same (carry-forward) — the guard is monotone, so output-time cleaning can only hide more — cost if wrong: about 40 µs extra per printed finding.
- **R24**: accept the residual that a value written in space-separated groups right after REPLACE_ME_ shows its first group (e.g. "NL91" of an IBAN, the first 4 digits of a card) — the word ends at the space, as ruled; country code + check digits or a card's first 4 digits are not secret (PCI allows showing the first 6) — cost if wrong: 4 characters of a grouped value printed in an error that blocks signing anyway.
- **R25**: accept message() cost (17–27 µs per param; a hostile 64 KiB tab file prints in 6.4 s) and [hidden] placeholders inside assignment-looking words — safety over speed on pathological input — cost if wrong: slow output on files that fail anyway.

## Task 1.3

- **R26** (for Task 1.4): after E-LIST-DUPLICATE, build_policy keeps each list entry once (first occurrence), so later checks and the Task 1.5 render see the list without the duplicate — otherwise one duplicate also raises E-BODY-DRIFT and per-entry warnings — cost if wrong: none (the file fails on E-LIST-DUPLICATE either way).
- **R27** (for Task 1.5): when split() or load() gives None (E-FM-MISSING, E-YAML, E-YAML-FEATURE, E-YAML-DUPLICATE-KEY), body checks are skipped (spec §1 lists only file, hidden-character, placeholder and content-safety checks as still running) — cost if wrong: body problems surface one round later.
- **R28** (for Task 1.4/1.5): when agent fails E-AGENT-ID or holds a placeholder, E-FILENAME, E-PRINCIPAL and E-BODY-TITLE are skipped — one defect, one code; otherwise one bad id cascades into three findings — cost if wrong: those checks run one round later.
- **R29** (for Task 1.5): E-BODY-DRIFT runs only when the front matter produced no errors other than E-PLACEHOLDER; warnings do not block it, so test cases for warnings must re-render the generated sections (rewrite()) — a render from an invalid front matter is noise, and an invalid file cannot be signed anyway — cost if wrong: drift shows up after the field errors are fixed.
- **R31** (for Task 1.4): tests use a test PlatformConfig with agents_project = AGENTS_PROJECT ("aiven-agents-test"), not config/platform.example.yaml ("aiven-agents-example") — otherwise the valid base fails E-PRINCIPAL — cost if wrong: none.
- **R32** (for Task 1.4): per tool entry, the first failing check in the order WILDCARD, R4 (reserved or R4 class), UNKNOWN, R3 decides; R0–R2 tools then get ABOVE-MAX-CLASS and FORBIDDEN independently, plus W-TOOL-NOT-LIVE — one defect, one code per entry — cost if wrong: a contradictory tool shows one code instead of two.
- **R33** (for Task 1.4/1.5): tool entries that failed their own checks drop out of every tool-list-dependent check (limits, scope, slack, W-TOOL-NOT-LIVE, E-BODY-TOOL-UNEXPLAINED) — avoids cascades — cost if wrong: dependent findings appear after the tool is fixed.
- **R34** (for Task 1.4): the forbidden baseline needs each of the four entries literally; one E-FORBIDDEN-BASELINE per missing item; list sizes use E-RANGE with value = entry count; W-TOOL-NOT-LIVE wrapper param is the display name (Drive, Email, Agent Builder) per spec §9 — the spec names no list-size code and shows "(Drive)" — cost if wrong: message wording.
- **R35**: accept MAX_DEPTH = 16 with E-YAML "nesting is deeper than 16 levels" — ruamel's pure scanner took 27 s on 10,000 "[" and 194 s on 65,000 — cost if wrong: none (schema nests 3 deep).
- **R36**: accept the implementer's interpretations: a placeholder field skips E-FIELD-TYPE (spec 3.1); a "--- …" marker inside the front matter is "second document"; a non-mapping root is E-FIELD-TYPE (field "front matter"); an empty front matter is an empty mapping; load(fm_text, path="") returns FrontMatter(data, lines, findings) — consistent with the spec and the 1.3 rulings — cost if wrong: small rework in 1.4.
- **R37**: the placeholder skip and check_filename use the scalar's raw source slice (what E-PLACEHOLDER sees); invariant test: every path in lines but not in data has a finding on that line — closes the fail-open — cost if wrong: none.
- **R38**: ruamel generator ValueError/OverflowError/AssertionError become E-YAML with a fixed detail; own exceptions propagate (E-INTERNAL in 1.8) — syntax errors must be E-YAML, and the verdict must not depend on python -O — cost if wrong: none.
- **R39** (SPEC CHANGE, flag to Matthijs at the M1 review): a backslash escape in a double-quoted scalar is E-YAML-FEATURE "escape sequence"; validator-spec §3.2 row updated — the signer must read exactly what the gateway enforces; escapes allow look-alikes, RLO/zero-width characters, lone surrogates and disguised placeholders, the same "you read one value, the gateway uses another" risk as duplicate keys; no v1 value needs an escape — cost if wrong: a future non-ASCII value needs a spec change (it would anyway: E-FM-NON-ASCII).
- **R40**: files above 1 MiB (16 × the limit) get only the once-per-file byte checks; nothing is decoded, scanned or parsed — bounded time and memory on hostile input (a big tab file made one Finding per character) — cost if wrong: an oversized file reports fewer problems, and it is invalid anyway.
- **R41**: M5 confirmed — "complex key" = a list or mapping in key position; an explicit "?" scalar key is accepted — cost if wrong: unusual but visible syntax passes.
- **R42**: keep the 1 MiB cap (R40) — CI runners and the signer's machine absorb the worst case (about 49 s, 579 MiB, on a file that is invalid anyway); the gateway path is closed by R43 — cost if wrong: a slow CI run on a hostile file.
- **R43** (for Task 1.7): verify() checks the byte cap and the signature BEFORE parsing; only a correctly signed file is validated (the signer validated it before signing). An unsigned or badly signed file gets E-SIG-MISSING/E-SIG-INVALID only — the gateway never parses untrusted bytes, so a hostile file in the control bucket cannot exhaust gateway memory — cost if wrong: a badly signed file's other problems are not listed in the gateway log (they are refused either way).
- **R44**: accept the implementer's judgement calls (C1 invariant counts a finding on the field's line or an entry's line; narrow placeholder skip: first raw line, scalar starting on the key's line; a comment after a block scalar indicator counts as value; markless E-YAML at the last event's start) — all fail toward more findings — cost if wrong: an extra finding or one line off.

## Task 1.4

- **R45** (for Task 1.4): a value that fails E-RANGE skips that field's warnings (min_runs 0 → E-RANGE only, no W-SHADOW-LOW) — one defect, one code — cost if wrong: none.
- **R46** (for Task 1.5): E-BODY-LINK covers link/image/autolink tokens plus any scheme:// or www. anywhere in the body, code spans and blocks included; E-BODY-HTML covers every html_block/html_inline token — the spec's reasons ("complete on its own", "text the reader cannot see") apply to code spans too — cost if wrong: a URL in backticks needs rewording.
- **R47** (for Task 1.5): rewrite() replaces from the "## Enforced rules (generated)" heading (found via tokens) to EOF and ends with one LF; it appends both sections when the heading is missing; render raises ValueError for a tool outside the catalog — the generated sections are the last two by spec order — cost if wrong: one function's edge behaviour.
- **R48** (for Task 1.5): E-BODY-SECTIONS also covers an extra level-1 heading and level-3+ headings outside the first three sections; E-BODY-EMPTY counts inline text (text, code_inline, softbreak as space) with whitespace collapsed; drift reports at the first differing line with diff_line = that line — the spec leaves these details open — cost if wrong: wording of one rule.
- **R49**: when any tool entry failed its own checks, skip W-LIMIT-UNUSED, W-SCOPE-UNUSED and W-MAX-CLASS-SLACK — the tool list is not settled, so "unused"/"slack" is speculative and cascades from the tool error — cost if wrong: those warnings appear one round later.
- **R50**: an exact forbidden entry inside a reserved namespace (payments.pay, agentbuilder.permissions) is accepted, not E-FORBIDDEN-UNKNOWN — it matches the reserved list, and the message "matches nothing in the catalog or the reserved list" would be false — cost if wrong: a redundant forbidden entry passes.
- **R51**: accept the other interpretations (build_policy(..., path=""); E-TOOL-FORBIDDEN one per tool at the tool's line; E-LIMIT-CONFLICT/W-LIMIT-UNUSED at the limit's line; a folder id without a Drive tool is W-SCOPE-UNUSED only, no E-SCOPE-MISSING for the path) — consistent with one defect, one code — cost if wrong: line placement only.
- **R52**: every file-derived field of Policy/Limits/Scope is repr=False (sha256 stays) — a Policy is built despite E-RANGE (R4), so a card- or BSN-shaped number would print via logs or tracebacks — cost if wrong: less helpful debug output.
- **R53**: R49 widened — the tool list is "unsettled" when an entry failed its own checks, holds a placeholder, or the list size fails E-RANGE; then W-LIMIT-UNUSED, W-SCOPE-UNUSED and W-MAX-CLASS-SLACK are skipped — they guess at tools that are not known yet — cost if wrong: warnings appear one round later.
- **R54**: drive_folder_path parts are [^/\s](?:[^/\r\n]*[^/\s])? (no line break inside a part) — the signer must read one path on one line — cost if wrong: none.
- **R55** (for Task 1.6): message() renders W-WIDENS {restart} per language from a "restart_runs" param, using the exact EN/NL sentences in validator-spec appendix A's note (empty when no restart); E-AGENT-DUPLICATE, E-PRINCIPAL-DUPLICATE, E-VERSION-ORDER (CI) and W-WIDENS are file-level findings; E-VERSION-ORDER in CI applies only to files whose sha256 differs from the previous ref's — a Policy carries no line map; an unchanged file keeps its version — cost if wrong: line placement only.
- **R56** (for Task 1.7): verify() order: (1) data over 64 KiB → E-FILE-SIZE, stop; (2) no sig → E-SIG-MISSING (agent from the file stem), stop; (3) ssh-keygen -Y verify fails → E-SIG-INVALID, stop; (4) validate; (5) load-only checks. At load, W-TOOL-NOT-LIVE is replaced by E-TOOL-NOT-LIVE: live = catalog status not planned AND wrapper_live(wrapper, agent); E-VERSION-ORDER at load = version below active, or equal with another hash; any exception → (None, [E-INTERNAL]) with detail = exception class name only — the gateway never parses unsigned bytes (R43) and always fails closed — cost if wrong: fewer diagnostics for a bad file at load.

## Task 1.5

- **R57**: accept the extra check — body lines no block token holds are reported (E-BODY-LINK for a link reference definition, E-BODY-HTML otherwise) — markdown-it silently drops content nested 20 deep, and a definition leaves no token, so hidden HTML/links would pass — cost if wrong: an exotic but harmless construct is flagged (fail closed).
- **R58**: E-BODY-DRIFT also skips when E-BODY-SECTIONS fired — section boundaries are unreliable then; one defect, one code (an extra section after Sign-off currently gives both) — cost if wrong: drift shows after the sections are fixed.
- **R59**: R46 enforced literally — the scheme:// / www. scan runs over the raw body lines (fenced-code info strings and reference definitions included), not over token content — "anywhere in the body" — cost if wrong: none.
- **R60**: accept the other choices (sections returned as they stand in a file; highest class = max_class; spend rendered from the file value; E-BODY-SECTIONS placement order) and the 1 MiB body cost (R42 class: CI only, the gateway verifies the signature first) — cost if wrong: small.
- **R61** (for Task 1.8): CLI config resolution --config → AIVEN_POLICY_CONFIG → config/platform.yaml → config/platform.example.yaml (stderr note); falling back to the example fails closed for real policies (E-PRINCIPAL) and lets the §9 command run as written; catalog default catalog/catalog-v1.yaml — cost if wrong: one flag in CI.
- **R62** (for Task 1.8): render runs only when the front matter loads and builds a Policy without errors (the drift condition); body/file findings never block it (template-to-policy path in §9); atomic write; verify CLI treats built wrappers as live and skips the folder check, with a stderr note; E-INTERNAL prints the exception class name only (no message, no traceback unless --debug) — cost if wrong: CLI ergonomics only.
- **R63**: hidden characters produced by decoding (character references) in text tokens or image alt text are E-BODY-HTML at the token's row; E-BODY-EMPTY and the reason test count only non-hidden characters — appendix A: "text the reader cannot see" — cost if wrong: none.
- **R64** (amends R47): rewrite raises ValueError unless the top-level ## headings from the Enforced heading onward are exactly [Enforced, Sign-off] or [Enforced]; also when the heading line exists without a heading token (unclosed fence); drift and rewrite both use top-level headings only — spec §1 "It changes nothing else" — cost if wrong: render refuses a misordered file instead of fixing it (the user reorders by hand).
- **R65**: the URL scan also runs over decoded text tokens; a line already reported by the raw scan gets no second finding — escapes and references build URLs after parsing — cost if wrong: one URL line reported once instead of per occurrence.
- **R66**: non-empty table body cells beyond the header's count are E-BODY-HTML on that row — GFM drops them silently (R57 class) — cost if wrong: none.
- **R67**: render wraps values in code spans with a fence longer than any backtick run inside (CommonMark padding rule), and drive_folder_path parts may not contain "`" (E-SCOPE-SANDBOX) — a value must never become prose in Enforced rules — cost if wrong: a Drive folder with a backtick in its name must be renamed.
- **R68**: accept the implementer's readings (decoded scan never duplicates the raw scan; stricter rewrite refusals; nested ## never completes the section sequence) — all fail closed — cost if wrong: none.
- **R69** (extends R64): rewrite also refuses when a top-level level-1 heading follows the Enforced heading — it would delete the author's text; such a file is already E-BODY-SECTIONS — cost if wrong: none.
- **R70**: the decoded URL scan skips an inline token when any of its rows was reported by the raw scan — no double finding — cost if wrong: one finding per paragraph instead of per line.
- **R71**: a fenced-code info string must be empty or one word [A-Za-z0-9_+.#-]+; anything else is E-BODY-HTML on the fence line — renderers hide the rest (R57 class) — cost if wrong: an author must drop extra info-string words.
- **R72** (SPEC TEXT, flag to Matthijs at the M1 review): validator-spec §3.7 E-BODY-HTML row now also names text the reader cannot see (decoded hidden characters, cells past the header, dropped lines, words after a fence's language) — commit 973c8c1 by the controller; appendix A message unchanged (it already gives that reason) — cost if wrong: wording only.

## Task 1.8
